# 늘봄(Elder Care) — 기획서 및 요구사항 정의서

## 1. 프로젝트 비전

독거 어르신이 스마트폰으로 AI와 가볍게 대화하고,
보호자는 상태·알림을 통해 안심할 수 있는
**AI 안심케어 서비스**를 만든다.

앱 이름(UI): **늘봄**

## 2. 문제 정의

- 독거 어르신은 일상에서 대화 상대가 부족하고, 이상 징후 전달이 늦다.
- 보호자는 멀리 떨어져 있어 상태 확인이 어렵다.
- 기존 케어 서비스는 비용·설치·학습 부담이 클 수 있다.
- 학생 팀 프로젝트 범위에서 **역할 분리 앱 + AI 대화 + 알림**으로
  핵심 가치를 검증한다.

## 3. 핵심 요구사항 (기능 요구사항)

| ID | 요구사항 | 설명 |
|----|----------|------|
| FR-1 | 역할 선택 | 어르신 / 보호자 진입 경로 분리 |
| FR-2 | 인증 | 각 역할의 로그인·회원가입, 로그인 유지 |
| FR-3 | 어르신 홈 | 메인 기능 진입(대화, 통화/이력, 건강 등) |
| FR-4 | AI 대화 | Gemini 기반 대화, 실패 시 Mock 응답 보조 |
| FR-5 | 통화 이력 | 통화 기록 저장 및 최근/전체/오늘 조회 |
| FR-6 | 보호자 홈 | 담당 어르신 목록·상세 |
| FR-7 | 어르신 관리 API | 등록, 조회, 검색, 건강상태, 관심 필요 대상 |
| FR-8 | FCM | 토큰 등록 및 푸시 알림 |
| FR-9 | 대화/채팅 API | 대화 저장·조회, WebSocket 채팅 구조 |
| FR-10 | 긴급/알림 화면 | 응급·헬스 알림 관련 UI |

## 4. 비기능 요구사항

- 어르신 UI: 큰 글씨·고대비·단순한 내비게이션
- 모바일 우선: Flutter 크로스플랫폼
- API 타임아웃·에러 처리 (앱에서 예외 메시지 표시)
- 민감 정보: Gemini API 키는 서버 설정(`application.yaml`/환경변수)으로 관리
- 팀 협업: backend / flutter_app 디렉터리 분리

## 5. 사용자 시나리오 (요약)

1. 어르신이 앱 실행 → 역할 선택 → 로그인 → AI와 안부 대화
2. 보호자가 로그인 → 어르신 목록 확인 → 알림/상태 확인
3. 이상 상황 시 푸시 또는 알림 화면으로 보호자 인지

## 6. 향후 확장 계획 (Future Work)

- 실제 음성 통화/STT·TTS 고도화
- 이상 행동·무응답 감지 규칙 고도화
- 보호자-어르신 매핑 권한/보안 강화
- 통합 E2E 테스트 및 스토어 배포용 빌드
